# WORK ITEM 1 — Get Requirement (AP Phase II)

**ระยะเวลาที่เสนอ:** จ. 28 ก.ย. – ศ. 2 ต.ค. 2026 (5 วันทำการ)
**Description:** ยืนยันขอบเขตการกระทบยอดฝั่งจ่าย (AP) ที่ระบบรองรับอยู่แล้วกับฝ่ายบัญชีเจ้าหนี้ และเก็บความต้องการเพิ่มเติมเฉพาะฝั่งจ่าย (เช็คสั่งจ่าย, การจ่ายรวมก้อน, ค่าธรรมเนียม/WHT/FX, รายงานเช็คค้างจ่าย) เพื่อสรุปเป็น scope ของ Phase II

### Subtasks

1. **สำรวจความครอบคลุมฝั่ง AP ของระบบปัจจุบัน (gap analysis)** — ไล่ทุกหน้าจอว่าเงินออกใช้ได้แค่ไหน แยกผลเป็น "ใช้ได้แล้ว / ใช้ได้แต่ต้องปรับ / ยังไม่มี"
   *Output:* ตาราง gap พร้อมอ้างอิงไฟล์จริง (ทำไปแล้วบางส่วนในเอกสารนี้)

2. **ประชุมเก็บ as-is process กับฝ่ายบัญชีเจ้าหนี้** — ปัจจุบันกระทบยอดฝั่งจ่ายอย่างไร ใครทำ ใช้เวลาเท่าไร ปิดงวดวันไหน ขอไฟล์ทำมือมาเป็นตัวอย่าง (แบบเดียวกับเคสกระดาษ BBL4633 ของฝั่งรับ)
   *Output:* as-is flow + ไฟล์ทำมือจริงอย่างน้อย 1 งวด

3. **สาธิตระบบปัจจุบันให้ทีมเจ้าหนี้ดู แล้วเก็บ feedback** — เปิดหน้า Reconcile แท็บเงินออก, Suspense, Reports ฝั่ง AP, Dashboard มุมมอง AP ให้ผู้ใช้ตัวจริงลองใช้
   *Output:* รายการ feedback แยกเป็น "ยืนยันใช้ได้ / ขอแก้ / ขอเพิ่ม"

4. **ตรวจขอบเขตบัญชีฝั่งจ่ายกับข้อมูลจริง** — พิสูจน์ว่า `BankAccountMapping` ตัดบัญชีที่ไม่ใช่ธนาคารทิ้ง (`PDC - R`, `TRANSFER`) แล้วทำให้ยอดฝั่งจ่ายหายไปหรือไม่ และฝั่งจ่ายมีบัญชีคู่แฝดที่ต้องนับด้วยไหม
   *Output:* ข้อสรุปขอบเขตบัญชี AP + รายการบัญชีที่ต้องเพิ่ม/ตัด

5. **เก็บ requirement เช็คสั่งจ่าย** — ปริมาณเช็คต่อเดือน, ระยะเวลาค้างขึ้นเงิน, เช็คหมดอายุ/ยกเลิก/stop payment, และ**พิสูจน์ว่าเลขที่เช็คในไฟล์ธนาคารตรงกับ BC365 พอที่จะใช้จับคู่ได้หรือไม่** (ฝั่งรับพิสูจน์แล้วว่าใช้ไม่ได้ ต้องพิสูจน์ซ้ำฝั่งจ่าย)
   *Output:* กติกาสถานะเช็คค้างจ่าย + ผลพิสูจน์เลขเช็คจากข้อมูลจริง

6. **เก็บ requirement กติกาผลต่างเฉพาะ AP** — ค่าธรรมเนียมธนาคาร/ค่าธรรมเนียมเช็ค, ภาษีหัก ณ ที่จ่าย, การจ่ายต่างประเทศและผลต่างอัตราแลกเปลี่ยน, การจ่ายรวมก้อน (media clearing / payroll)
   *Output:* ตารางกติกาการจับคู่ฝั่ง AP + ค่าผลต่างที่ยอมรับได้

7. **เก็บ requirement รายงานฝั่ง AP** — รายงานเช็คค้างจ่ายแยกอายุ และ Bank Reconciliation Statement มาตรฐาน (ยอดตาม statement ± เช็คค้างจ่าย ± เงินระหว่างทาง = ยอดตามบัญชี)
   *Output:* ตัวอย่างหน้ารายงานที่ผู้ใช้ยืนยัน

8. **กำหนดสิทธิ์และการแบ่งงานระหว่างทีม AR / AP** — ต้องเห็นข้อมูลข้ามกันไหม ต้องมี role หรือตัวกรองแยกฝั่งไหม และใครจะเข้า UAT
   *Output:* role matrix ฉบับปรับปรุง + รายชื่อผู้ใช้ UAT

9. **สรุป scope และ requirement sign-off** — แยกให้ชัดว่าอะไรคือ "ของเดิมที่ยืนยันแล้ว" อะไรคือ "งานใหม่ของ Phase II" และอะไรยกไป Phase ถัดไป
   *Output:* เอกสาร scope ลงนามโดยหัวหน้าฝ่ายบัญชี
